APPEAL – GUIDELINE 2.5.1, InstaBlock 1.0

We respectfully ask that the 2.5.1 rejection be reconsidered, or that App Review name the specific API it considers misused so we can address it. The app uses one public API, as documented, for a purpose already permitted in many App Store apps.

1. WHAT THE APP DOES
InstaBlock is an on-device network filter the user installs to stop compulsive short-form video scrolling. Instagram Reels and TikTok videos stop loading while Instagram direct messages, stories, comments and photos keep working. There is no server, no account and no data collection.

2. THE API AND HOW IT IS USED
The app uses a single Network Extension API, NEPacketTunnelProvider configured through NETunnelProviderManager, with the standard packet-tunnel entitlement. It is used exactly as documented: the provider receives packets for the routes and DNS match domains it declares in NEPacketTunnelNetworkSettings and decides what to do with them.
- It declares no default route. Only DNS for a short list of media CDN domains (fbcdn.net, cdninstagram.com, tiktokcdn.com and related) and connections to the addresses they resolve to enter the tunnel.
- DNS queries are forwarded unchanged to the network's own resolver and the real answers returned.
- Connections to those addresses get a per-host firewall policy: TikTok's video hosts are blocked; Instagram's media hosts, which also serve photos, are bandwidth-limited so photos load and video does not.
No private API, no undocumented behaviour, no code injection, and no interaction with the Instagram or TikTok apps. The app does not read, decrypt, modify or redirect their traffic. It applies a network policy to a set of hosts, which is the documented purpose of a packet tunnel provider.

3. THE SAME PATTERN AS APPROVED APPS
On-device firewall and content-blocking apps built on NEPacketTunnelProvider with no remote server are an established App Store category (Lockdown Privacy, AdGuard, 1Blocker's firewall, NextDNS). They block connections to listed hosts, several with per-service rules. InstaBlock applies the same mechanism to a narrower host list and adds a bandwidth limit, a standard firewall/QoS capability, instead of an outright block, so users keep photos and messages.
The rejection says the app uses APIs "to stall content". The app does not stall or degrade Instagram or TikTok themselves; it restricts the network path to specific video-delivery servers at the user's explicit request, as a firewall app restricts the path to ad or tracker servers. The user installs InstaBlock for exactly this effect and grants it through the system "Add VPN Configurations" dialog. The mechanism is disclosed on the first-run screen, in the App Store description and in the privacy policy.

4. GUIDELINE 5.4
The app uses the NETunnelProviderManager API as required, does not sell, use or disclose any data, has no ads or monetization, and clearly discloses its use of a VPN configuration.

5. NO ALTERNATIVE API
Screen Time APIs (FamilyControls, ManagedSettings, DeviceActivity) can only shield whole apps or Safari domains; they cannot keep Instagram messaging working while stopping Reels, which is the entire point. NEFilterDataProvider and NEDNSProxyProvider require supervised devices. NEPacketTunnelProvider is the only public API that can apply a per-host network policy on an unsupervised iPhone.

6. REQUEST
Please approve the app, or identify the specific API and usage considered outside the documentation so we can change it. We are glad to supply the extension's DNS and packet-handling source, a screen recording, or any other detail.

Thank you for your time.
